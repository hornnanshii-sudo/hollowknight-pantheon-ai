# 开发路线

## M0：环境验证
确认游戏版本、Mod API、独立训练存档与构建 SDK。安装 Mod 前备份存档。以 Hornet 建立一个实例的训练接口，检查观测与动作严格对应同一个游戏步。

## M1：单 Boss 基线
实现 Gymnasium 环境、PPO 基线、日志与 checkpoint。先做短跑基准，再执行至少 100 局独立评测。控制频率 20 Hz 只是起始配置，需要实测。

## M2：扩展 Boss
建立 Boss 清单与五门场地配置。覆盖多敌人、弹幕、平台、阶段切换。提前验证纯粹容器和无上辐光。维护历史 Boss 的复习采样，防止遗忘。

## M3：连战
从两场相邻战斗开始，扩大到 3–5 场及休息点之间的完整段。测试资源连续性、休息和治疗行为。

## M4：五门
正常规则下跑完整五门，统计失败位置与通关率，并将真实失败状态反馈到专项训练。训练重置与最终评测模式必须明确隔离。

## 运行资源
从单实例 CPU 小网络开始，测量每秒有效采样步数。再比较 2/4 实例。AMD GPU 后端须通过前向、反向和完整 PPO 更新测试后使用，不直接采用 NVIDIA CUDA 安装命令。
