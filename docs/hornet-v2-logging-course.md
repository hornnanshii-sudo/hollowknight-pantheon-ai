# Hornet v2：先记录、验证，再重新训练

旧运行在累计采样 12000、有效更新 11017 保存停止。旧权重不用于新实验训练。原 200000 总预算不扩大：A/B 各 5000，之后新模型最多 178000；所有失败采样仍占总额度，评测另计。

## 新增日志

每步压缩 JSONL：四个动作头的完整概率和熵、选中动作、请求按钮/脉冲、实际 input_mask、物理 tick 与 dt、通信耗时、双方位置速度、Boss 原生 FSM 及持续时间、地形射线、危险对象、命中/受伤事件序列和奖励分项。

每局 diagnostics.jsonl：首个有效命中时间、总伤害/受伤/实际攻击、横向活动范围、靠墙时间估计、靠墙无伤害时间估计、最长无命中时间、每个动作计数、各头平均熵、dt 范围、通信延迟 p95。靠墙用原生地形射线距离 <1 判定，只作诊断，不参与奖惩。日志保留 normal/near-left/near-right 与随机/确定性模式。

## 本次发现和修复

1. 旧 reset 条件过早：落地不等于控制已恢复。现在还要求原生 can_jump/can_attack/can_dash 全部可用。
2. 跨局竞态：reset 后必须看到新 epoch；开局调整仅在新场景 armed 后执行，防止上一场状态被当成新开局。
3. 10 项原生动作探测通过：左右移动、左右移动跳跃、左右移动攻击、上下攻击、左右冲刺。未经充分验证的完整胜利条件仍保持未验收。
4. 同一旧检查点两局确定性与两局随机评测：确定性分别 818/886 次全部向左，靠墙约 31.0/34.7 秒；随机分别靠墙约 4.6/5.7 秒。移动头熵约 1.09（最大 log(3)≈1.099），支持“轻微方向偏好被 argmax 放大”，不能称为策略已完全塌缩。四局不足以证明一般规律。

## 单一变量的开局课程

只调整开局时小骑士位置与朝向：Boss 落地、双方未受伤时放到 Boss 左右 4.5 单位，检查地面与地形不重叠，调用原生转向。Boss 的血量、速度、碰撞、伤害、出招均不修改。正常评测全部原生开局。

辅助开局概率：新模型前 5000 步 75%，5000–20000 步 50%，20000–40000 步 25%，此后 0。左右各半。保留正常开局防止只学辅助条件。6 次实机验证全部通过，失败的中间版本报告另存。

保持 LSTM/动作空间和奖励：伤害 /9，受伤 -1/血；无贴墙/空挥/按钮/持续位置奖励。窗口进展奖励因恢复窗口未验收，不实现猜测性奖励。原有完整击杀门槛不伪造通过。

## A/B 与重新从零

`hornet_v2.py` 顺序执行：ab-native 5000 步 → ab-course 5000 步 → fresh-selected。

A/B 使用同一初始权重种子、空优化器、相同超参数；每组后各 3 局确定性、3 局随机的正常开局筛查。游戏 RNG 未控制，样本很小，只是操作性筛查。辅助组仅在平均伤害更高、平均掉血不更高、命中局数不少时被选中，否则保留修复后的原生开局。不得声称统计显著。

随后再次构造新模型、新优化器，从 0 训练选定方案，绝不继承 A/B 权重。每 1000 步保存权重、优化器、随机数状态和账本；每 5000 步做 10 局确定性＋10 局随机正常开局评测。疑似击杀或时序/事件错误会停止并保留证据，不自动越过错误。总预算 200000 用尽结束。
